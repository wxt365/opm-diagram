## 工作流程

1. 先 `read_model`，结合需求、本图、父子背景和未提交方案确定本图要回答的问题。系统级建模明确价值、受益者、核心功能及系统/环境边界；局部编辑不强补系统总览。结构或资源任务不编造过程，不把说明或无业务含义的“开始/结束”做成节点。
2. 复用语义匹配的本图 occurrence；新图元使用稳定、唯一的 local_id，后续 target/endpoints 引用已有别名。同名不代表同一对象，近义词也不是合并依据。跨图同一实体应共享身份；父图元素在本图没有 occurrence 时不能新建同名副本冒充继承。
3. 先实体/过程，再关系；用 `get_capabilities` 的真实候选、端点顺序和 capability_id。按 `read_model` 的步骤 schema、relation_rules、layout_rules 操作，不编造能力或以屏幕位置推断关系方向。
4. 用 `stage_change` 连续完成整图或整组修改，实时展示预览；续聊保留正确步骤与别名，不逐元素询问、不让用户回复“继续”。重大业务歧义集中澄清，其他假设在最后说明。
5. 服务完成平台诊断及独立审查后，按工作台指定的方式保存。最终检查或受阻恢复修正时用 `revise_plan` 替换未提交方案，保留合理内容并重新检查。不能删除真实模型或语义撤销；仅当 read_model.modeling_context.capabilities.create_subdiagram 为 true 时，使用 stage_subdiagram 将本图内部细节下沉到新直接子图，不修改其他既有图。查看 affected_views 的主图/子图边界与同一身份，全部受影响图均须通过审查。能力为 false 时仅提供建议。建议与已生成内容分清，不声称预览已应用，不输出 CWOPM 工程 JSON。

## 建模决策

初始OPD生成完成全部需求且暂存成功后调用 finish_generation，立即进入诊断与审查，不以文字回复替代完成信号。不能提前完成半张图；有失败步骤先修正。仅解释或澄清无方案时正常结束即可。成功暂存且步骤变化计为进展，重复查询或无变化重放不延长无进展时限；总生成仍有上限。

生成暂存或最终检查被拒绝时，先 read_model，按实际返回核对失败步骤、原方案和 plan_diagnostics.current.repair_attempt 的诊断，再依据 schema 与真实能力检查字段、身份引用、端点类型及顺序、状态归属。仅在当前工具权限内自动修正有确定依据且不改变业务含义的编码错误；涉及业务解释、身份或关系含义变化而证据不足时集中澄清，不猜测、不扩大修正权限。

自动修正用 revise_plan 提交完整方案，保留正确步骤、身份和合理布局。区分无效编码与其承载的业务需求：移除无效或重复项须有证据，未表达内容及能力限制必须列明，不能靠删除必要对象、关系或约束消除错误。相同诊断下不无变化重试；网络、鉴权及版本冲突交由相应恢复流程，不当成模型编码错误反复修正。

revise_plan 成功只表示暂存。完整修正版无失败步骤后调用 finish_repair，服务重新诊断与独立审查，通过后按工作台指定方式保存。此工具仅修正阶段可用，不在完成后继续写入；仍有未解决或未表达需求时不得声称完整通过。

过程子图需要隐藏内部过程时，在重组步骤设置 abstract_boundary=true，父过程的业务范围必须覆盖所选细节。后端仅派生基础输入/输出/使能/调用边界，原事实保留子图且父关系 boundary_source_fact_id 指向来源。状态指定、控制修饰等复杂边界不自动猜测；能力拒绝时说明具体限制，不能反复尝试同一不可表达修正。对象子图仍用共享端点模式。revise_plan可保留步骤身份并显式修改该开关，不能只补成员后声称边界已解决。

- 按存在性、时间性及变换作用区分对象与过程，不仅凭词性。核对过程前置对象、状态、使能条件，以及完成后的生成、消耗或状态变化；不要求每个过程产生新对象，父过程可在子图揭示内部实现。
- 不同对象的投入产出用 Consumption/Result，同一对象的状态改变才用 Effect，不能用不同对象的状态拼接。人员/设备使能与被变换对象分清。同一层级、同一过程、同一对象或状态核对角色冲突；消耗 A、生成 B、影响 C 可共存，合法状态限定关系不按端点简单去重。
- 互斥状态属于同一维度；可同时成立的维度考虑属性及属性对象状态。初始/终止分别对应系统开始/结束或对象生成/消耗；默认表示随机观察最可能出现的状态，最多一个且不等于初始，初始/终止可多个或没有。数量、单位、多重性、值域按需求表达，未知不编造。
- 区分事件触发、普通前置等待与条件跳过：普通前置不满足时等待后续触发及条件满足，条件连接不满足时跳过。不能把所有“如果”都做成条件连接，能力不足时列未表达内容。
- 同一过程同类普通多条连接具有 AND 语义；同类连接扇形分歧端恰一个对象存在或过程发生用 XOR，至少一个用 OR。未知逻辑不猜，不用伪“选择”节点替代连接符。结构区分整体/部分、特征、泛化/特化、类/实例；普通关联不证明组成，除特征外不混接对象与过程。
- 系统归属、物理/信息属性及控制符只用原生能力表达；缺平台字段不等于业务事实缺失。关键约束不能以颜色、说明节点代替。区分需求事实、假设、能力限制与尚未表达项。
- OPD/OPL 核对只用服务最终预览生成的同版本 OPL。缺失时说明尚未核对，不能把助手文字当 OPL；发现不一致修正暂存模型或报告生成器问题，再生成审查，不润色文字掩盖错误。

## 每张图的可读性

每张 OPD（含各层子图）主要对象与过程合计约 8～15 个作为规划目标；少于 8 个不凑数，超过 15 个评估阅读负担，不机械切图或删除必要事实。计入状态/属性的节点阈值、间距等读取 `quality_policy`；这些是非阻断偏好，不是标准门槛，用户有意的密集、同名或指定坐标可保留并说明。

一图聚焦一个主要问题，但不限制只能有一个过程。总览保留核心转化、主要投入产出和必要使能。拥挤时按原因选择：内部步骤细化为过程子图、真实组成按结构展开、状态按上下文显示、异常保留触发入口及恢复结果再细化。隐藏/折叠不删除事实，部分显示只用平台支持的省略表达，不能把无关对象打包。

存在合理边界且拥挤影响理解时主动建议拆子图：指出已有过程/对象、子图名称与问题、移入细节、父图保留内容及外部转化/使能对应；各子图仍适用同一目标。允许内部中间对象与细化状态，不要求父子关系逐条相同。公共资源仅有业务依据时提升到父过程。当前工具不能拆图时完成可表达的本图内容并说明后续范围；脑图转图不得静默丢弃需求，也不增加逐步确认。

名称简短明确，定义、来源和长说明放支持的详情。按预览中的实际尺寸为长名称、多行标题及状态预留空间，不能只按固定中心间距排布或缩小正文来掩盖重叠。主转化链清晰，使能资源在外围，分支与孤立组留出通道；新增内容优先局部调整，保留合理旧坐标及用户手工布局。颜色仅辅助，不能替代形状和连接语义。

状态放所属对象或属性容器内，创建时可省略 layout，位置和扩容以 Runtime 预览为准；容器内状态与所有者的正常包含不是碰撞。属性在所有者外侧展开时，将所有者、属性子树及其状态作为完整组预留空间，不能只检查对象矩形。属性仍是属性，不为排版改成独立对象；当前工具没有 CREATE_FEATURE，不伪造属性创建步骤。

关系沿用画布的正交避障与关系标记。安排节点时为转弯、分支及文字留白，避免无关节点正文遮挡；具体路由交给画布，不编造连线命令，不为减少交叉修改端点、关系种类或删除事实。复杂多对多关系仍可能交叉，不能声称所有连线无交叉。

区分布局入口：新导入模型由导入流程逐图检查几何，AI 的 stage_change 不等于重新导入，也不自动调用全模型整理。当前工具只能按本图实际能力暂存布局；已有模型的全图整理入口是“布局工具 → 整理整个模型”，由用户预览、应用到全部图并保存草稿。除受支持的子图重组外，不能修改其他既有图或声称已整理全部子图。

quality_policy 是当前图的启发式建议，不是布局算法参数或几何验收：节点计数包含属性和状态，密度及长连线提示不等于布局错误；现有间距检查不覆盖完整属性组、文字及路由。不能把“无质量建议”当成全模型无重叠或无交叉的证据，也不为通过阈值删减内容。

严格过程内缩放中，子过程椭圆顶部从上到下表示名义次序，同高度表示并行调用且各需前置条件；对象内缩放可能表示空间或逻辑顺序。仅在明确上下文中保留这些语义，不把普通子图、聚合或脑图分组当内缩放。指定坐标与明确顺序冲突时说明，不为美观改语义或声称两者都满足。

维护者：数值仅维护于[质量策略](references/quality-policy.json)，由 `read_model` 返回；正文随指导版本发布。

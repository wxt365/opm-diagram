# OPM 桌面客户端增量需求

版本：0.2；日期：2026-11-16；状态：开发态实现已落地；运行证据见[实现清单](../checklists/opm-desktop-client-implementation-feature-checklist.md)，首版发布矩阵未全量验收。

本需求补充[产品需求基线](opm-online-modeling-tool-requirements.md)，对应[桌面设计](../design/opm-desktop-client-design.md)。不改写原冻结状态，不替代现有 Web 部署，也不把原有功能自动认定为桌面端已通过验收。

## 1. 目标与使用方式

用户安装应用后，通过一个独立窗口完成项目管理、脑图分析、OPD 建模、OPL 查看、平台校验、保存与导入导出，不需要先安装 Java、Node.js、数据库或手工启动服务。模型业务数据在本机 SQLite 中持久保存。

核心建模可离线使用；智能助手需要用户配置可用的模型服务并联网。没有 API Key、断网或模型服务不可用，均不能阻止用户打开应用和继续手工建模。

## 2. 平台与首版范围

| 项目 | 首版目标 | 边界 |
| --- | --- | --- |
| macOS | Apple Silicon（arm64）与 Intel（x64）分别提供安装包 | 不把一台机器的测试替代另一架构验收；是否合并 Universal 包后置 |
| Windows | Windows 11 x64 安装包 | Windows 10、Windows ARM64 后置评估，不承诺已支持 |
| 最低 macOS 版本 | 目标 macOS 13+，Electron 45.3.2 分发包声明下限 13.0 | 安装包必须标明；全部随包运行时及最低系统仍需在干净设备验收 |
| 安装形态 | macOS `.dmg` 内应用，Windows `.exe` 安装程序 | 首版不进入应用商店；签名、公证由发布阶段验证 |
| 本地存储 | 业务模型使用 SQLite，沿用每项目一库和目录库 | 附件、Profile 资产及既有助手会话文件仍存受控目录，不强行迁入数据库 |
| 智能助手 | 保留现有 DeepSeek 对话、预览、校验及最终确认流程 | 不附带开发者密钥，不将 AI 在线能力表述为离线能力 |
| 升级 | 手工安装新版，应用数据保持 | 首版不实现自动更新或后台下载 |

## 3. 功能要求

下表的 MUST 是桌面版发布验收要求，不代表本轮已经实现。

| ID | 优先级 | 要求 |
| --- | --- | --- |
| FR-DESKTOP-001 | MUST | 按上述三种 OS/CPU 目标交付可安装、可启动和可卸载的客户端；安装和启动不依赖源码目录或开发工具。 |
| FR-DESKTOP-002 | MUST | 随包提供前端构建产物、本地 Runtime、匹配架构的 Java 运行时、模型 Profile/规则/语法及必要依赖；运行时不下载核心组件。 |
| FR-DESKTOP-003 | MUST | 无网络、无 Key 的首次启动可创建项目、模型及父子 OPD，编辑脑图和画布，查看本地生成 OPL、执行平台校验、保存及导入导出；需要大模型的转换审查等操作明确提示联网条件。 |
| FR-DESKTOP-004 | MUST | 本地 Runtime 显式使用 SQLite，项目、模型、草稿及业务版本经正常关闭、服务重启和再次打开后保持；不连接 PG，不因 SQLite 出错切换空库。 |
| FR-DESKTOP-005 | MUST | 桌面版与 Web 版复用同一建模、校验及保存契约；UI、桌面壳和助手不得绕过 Runtime 直接写业务数据库。 |
| FR-DESKTOP-006 | MUST | 第一次运行显示就绪进度，后端、资产及数据目录检查完成后进入工作台；启动失败提供原因、重试和诊断入口，不无限显示空白页。 |
| FR-DESKTOP-007 | MUST | 同一应用数据目录只允许一个受管客户端实例写入；再次打开聚焦原窗口。端口冲突不结束用户其他服务，也不附着到身份未知的本地进程。 |
| FR-DESKTOP-008 | MUST | 退出应用前处理未保存编辑、活动写事务及 AI 任务；不将暂存提案自动确认为正式模型，不静默丢失数据；关闭后回收本应用管理的 Runtime、助手和 Harness。 |
| FR-DESKTOP-009 | MUST | 设置页显示数据位置、版本与诊断入口；数据保存于用户应用数据目录，与安装目录、临时目录及开发环境 `runtime-data` 隔离。升级及默认卸载不删除用户数据。 |
| FR-DESKTOP-010 | MUST | 支持完整用户工作区的备份和恢复，涵盖目录库、各项目库、必要资产、助手会话/附件及恢复清单；备份排除可再生缓存、日志和系统绑定凭证。恢复前校验兼容性，不覆盖活动数据库。 |
| FR-DESKTOP-011 | MUST | 数据库升级前取得一致性备份；迁移失败停止打开相关数据并给出恢复选择，保留失败证据，不删除原目录、不自动运行反向 DDL。 |
| FR-DESKTOP-012 | MUST | 用户可配置、修改、清除和测试 DeepSeek Key；Key 使用操作系统支持的加密保护，不进入安装包、模型交换文件、工作区备份或日志，保存后不向渲染进程回传原 Key。无法安全保存时仅会话内使用或不启用 AI。 |
| FR-DESKTOP-013 | MUST | 未配置 AI 时独立显示助手不可用及设置入口；配置后多轮对话、实时预览、受限修正、平台校验、独立审查、一次确认与重开恢复均可用。API Key 失效或 AI 进程失败不导致本地画布服务退出。 |
| FR-DESKTOP-014 | MUST | 保留模型及 OPD 的现有导入导出入口，用受控文件选择/保存交互完成；旧 Web 环境的模型通过已支持的交换格式迁入，不扫描或覆盖本机开发数据库。 |
| FR-DESKTOP-015 | MUST | 支持日志查看/打开日志目录及脱敏诊断导出，显示失败组件与应用/运行时版本；导出前由用户确认内容，不自动上传模型、聊天或附件。 |
| FR-DESKTOP-016 | MUST | 安装新版前关闭旧实例并备份数据，保留原项目身份与内容。数据库不兼容时不能直接以旧应用打开新库；回退通过旧版本和升级前备份完成。 |

## 4. 非功能要求

- NFR-DESKTOP-001：仅监听 loopback，保留既有会话和 Origin 校验；渲染进程无 Node、数据库、任意文件读写或任意进程启动权限。
- NFR-DESKTOP-002：启动、退出、异常恢复与备份有明确进度和失败出口。性能阈值沿用实际建模基线；新增冷启动时间、总内存和安装包大小在 PoC 中测量后冻结，不先声称轻量。
- NFR-DESKTOP-003：提供可追溯的构建清单，包括源码修订、Web/Java/Node/Electron/原生依赖版本、目标 OS/CPU、资源摘要及许可证清单；签名私钥不在仓库和普通构建产物中。
- NFR-DESKTOP-004：三个目标包分别进行干净环境安装验收；必须覆盖中文及带空格路径、标准用户权限、无系统 Java/Node、端口冲突、无网络、数据库锁定、磁盘不足与异常退出。
- NFR-DESKTOP-005：正式分发的 macOS 包通过签名及公证验收，Windows 包通过代码签名验收；没有证书时只标为开发测试包，不声称已满足正式分发条件。

## 6. 首版非目标

不实现多设备同步、多人协作、云端托管、PG/SQLite 自动迁移、MySQL/达梦客户端模式、便携 U 盘运行、自动更新、商店发布或 Linux 客户端。不因桌面化宣称完整 ISO 符合性，也不开放助手的 shell、任意文件和数据库工具。

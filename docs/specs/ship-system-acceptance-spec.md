## 验收

- A01：项目列表、项目详情、原模型打开；记录模型规模、OPD 层级、错误及截图。
- A02：从原模型根 OPD 通过 UI 导出，并在独立项目通过 UI 导入；核对语义数组及层级规模。
- A03：逐个 OPD 打开，验证画布、OPL、导航、视口适应；记录性能；异常独立记录后继续。
- A04：副本节点增删、名称编辑（含非法空白）、撤销/重做、布局移动及保存后重开一致性。
- A05：副本手动保存、自动保存、历史版本只读及返回编辑。
- A06：校验/findings、架构方法、思维导图、操作历史、助手面板；有支持的入口均走真实 UI。真实外部 AI 推理另行记录，不能用 mock 通过冒充。
- A07：副本损坏导入拒绝、失效 URL、编辑响应丢失恢复和不同宽度浏览器布局。
- A08：副本导出往返一致性、原模型语义未变；每项状态 PASS/FAIL/BLOCKED，失败包含截图、错误和复现步骤；不因发现产品错误而自动修改产品。

### 证据和判定

每项保存动作源码（复现步骤）、运行时 URL、开始时间、耗时、截图和异常堆栈；记录未捕获 pageerror、console error、HTTP >=400、requestfailed。全程 Playwright trace 可用 `npx playwright show-trace <trace.zip>` 查看，报告生成 JSON 和 Markdown。命令非零退出表示 FAIL、BLOCKED 或致命异常，不能据此直接认定产品缺陷。

失败需分为：产品功能/布局/数据错误、业务模型质量观察、外部助手错误、测试驱动/定位器错误、环境阻塞。有意注入的 503/网络丢失、不存在资源的 404 和历史快照的可选测试故障入口 404，按上下文解释；意外 4xx/5xx 单独调查。模型重复父边界关系不能仅凭重复 OPL 认定存储损坏。

完成标准：矩阵每项有实际运行结果；所有测试驱动错误修正并重跑；产品问题即使未修复也必须列出证据和影响；前后原模型保护检查完成。不要求为了全绿修改产品或原模型。

### 未覆盖范围与后续专项

本方案覆盖当前船舶用户旅程及主要界面功能，并不证明 100% 代码/业务规则覆盖。浏览器跨引擎（Firefox/WebKit）、长时间并发、多窗口竞态、后端断电/磁盘满、SQLite 损坏、真实权限攻击、全部 PROC/CTRL/STRUCT 规则组合、助手新增整图/多轮改写/审查与自动应用，需要独立隔离环境和专项用例。真实 MySQL/PostgreSQL/PostGIS 在船舶模型中是建模对象，本次没有外部业务数据库连接验收。性能记录为单次耗时，未制定生产 SLA，不伪称负载基准通过。

### 运行与复现

1. 启动项目现有服务；确认以上端口对应当前版本。
2. `node tests/system/ship-acceptance.mjs`；无新增依赖，默认使用本机 Edge。
3. 运行 `node tests/system/audit-ship-evidence.mjs <本次输出目录>`：独立核对全部语义数组、原模型保护和四图节点/边数量，生成模型重复关系观察。可设置 `OPM_ACCEPTANCE_BASE`、`OPM_SHIP_PROJECT`、`OPM_SHIP_MODEL`、`OPM_ACCEPTANCE_BROWSER` 换到明确的测试实例。
4. 查阅控制台输出的 `tests/system/output/<UTC timestamp>/report.md`、`report.json` 与逐项截图；使用副本 URL 复现。
5. 发现失败保留该次证据，修正测试驱动后新建副本全量重跑；旧记录标为试跑，不能混入最终通过统计。

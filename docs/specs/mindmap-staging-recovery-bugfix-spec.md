# 脑图转换暂存失败自动修正

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change；Risk Level: L2；Task Type: bugfix；Active Playbooks: testing (primary)。

## 目标与证据

本地历史脑图 revision 5 的前 38 步只读预览成功，第 39 步 create.rel.7 将两个过程以 CAP-ISO-PROC-006 连接，返回 DRAFT_EDIT_REJECTED / ENDPOINT_KIND_MISMATCH。当前 convertAnalysis 在暂存循环抛错后直接结束，未进入最终审查修正，也未记录失败步骤。既有测试只覆盖成功编译与最终审查，缺少生成中被 Runtime 拒绝的路径。

目标：将可诊断的暂存错误交给受限助手修正；保留成功预览、完整转换基线和原脑图，修正通过后再执行平台全模型诊断和独立审查，最终仍由用户确认。

## 范围与边界

允许：apps/assistant/src 的脑图转换及诊断、apps/assistant/test 的定向回归、相关 docs/specs 与 docs/checklists 及助手使用说明。新增局部模块可复用现有 runStage、revise_plan、finish_repair 及来源协调逻辑。

禁止：修改公共 HTTP API、schema、数据库、依赖、正式模型或用户脑图；扩大工具权限；吞掉鉴权、版本冲突、网络、停止或超时错误；为通过校验静默删除需求；无关重构。

## 验收

- A1：关系暂存出现端点/参数错误时记录失败步骤，后续独立步骤继续预览，并自动进入受限修正；不把部分成功当作整图完成。
- A2：修正读取完整原转换方案和失败证据，仅沿用现有允许的移除/恢复/布局调整能力；移除项可追溯且向用户说明。业务歧义或无法表达的需求不得伪造通过。
- A3：修正后必须完成正常最终校验与独立审查才能 ready；修正无效、未完成或停止时保持不能应用。
- A4：版本、鉴权、网络等非模型错误立即终止；失败的首个步骤也不能丢失诊断。分析续聊获得失败原因及步骤。
- A5：本地案例的历史第 39 步能够稳定复现；使用只读预览验证修正流程，不应用方案。所有新增回归及助手测试通过。

## Plan

1. 在暂存阶段区分可修正输入拒绝与运行故障，收集失败步骤并保留完整基线。
2. 复用受限修正工具闭环，成功后进入既有最终校验流程。
3. 补充分析诊断和能力提示，覆盖成功恢复与不可恢复路径。

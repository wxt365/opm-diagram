# 助手会话保存重试

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change; Risk Level: L2; Task Type: bugfix; Active Playbooks: none (primary).

## 目标与边界
修复 Windows 短暂文件占用导致会话替换立即失败的问题。允许修改 apps/assistant/src/store.mjs、新增对应存储测试及本规格/清单。允许新增保存错误码和用户提示；不改变 HTTP 路由、schema、依赖、安全校验、模型持久化、其他模块或 .harness。非目标：多进程锁、文件 ACL 修复、会话初始化错误和重构读写队列。

## 验收
- STORE-01：EPERM/EBUSY 采用 50/100/200/400/800ms 有限重试，成功后完整替换原文件。
- STORE-02：持续失败或其他错误不删除原文件，清理本次临时文件；不重试其他错误。
- STORE-03：用户仅收到可重试保存错误，不泄露路径；服务端记录底层错误码、尝试次数，不记录会话内容或令牌。
- STORE-04：失败后同一会话的后续 update 可以继续成功。

## 计划与验证
保留原子替换和既有 update 串行队列；通过可注入 rename/延迟操作测试故障分支。先运行存储定向测试，再运行助手全套测试。完成后重启服务验证健康。不扩大到读写锁：有限重试先处理读文件或外部扫描造成的短暂占用，持续占用仍明确失败。

## 回滚
恢复 store.mjs 并重启助手；保留 conversations 原文件，不重置数据。

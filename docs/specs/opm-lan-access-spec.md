# 本机多地址访问

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change；Risk Level: L3；Task Type: feature。
Active Playbooks: backend-springboot (primary)、frontend-vue、testing。

## 目标与边界

前端监听所有 IPv4 地址，通过本机局域网 IP 使用建模及助手。后台继续只监听回环地址，由 Vite 代理请求。默认后台来源规则保持回环限制，部署者通过 `OPM_TRUSTED_WEB_ORIGINS` 显式启用额外页面来源。

允许修改 `apps/web/vite.config.ts`、助手 HTTP 入口及配置示例、Runtime 来源守卫和配置装配、对应测试、本规格及检查清单。允许增加配置项及扩展来源白名单；不改变 API 请求/响应、schema、依赖、持久化或业务规则。不修改其他模块、模型数据、`.harness`、Git 远端，不引入登录或公网部署。

来源白名单按完整 `scheme://host:port` 匹配，不接受通配符、路径、凭据、查询或片段。仅在后台 Host 仍为回环地址、页面 Origin 命中白名单、会话令牌有效时放行。助手内部工具认证保持原行为。

## 验收

- LAN-01：5177 监听 `0.0.0.0`，回环地址和本机 IP 均可加载页面、Bootstrap、项目列表。
- LAN-02：受信任 LAN Origin 的 v1、v2 和助手请求通过来源检查；未配置 LAN Origin、其他端口/域名、缺少或伪造会话均拒绝。
- LAN-03：后台和助手维持 `127.0.0.1` 监听；已有回环访问、v2 错误格式及内部工具认证保持兼容。
- LAN-04：提供启动、配置、IP 变化处理和回滚说明，不输出密钥或会话令牌。

## 实施计划

1. 前端默认监听所有地址；使用额外可信来源配置扩展现有守卫，保留旧构造方式供现有测试使用。
2. 增加来源与令牌正反例测试，验证 Spring 配置装配和 v2 复用。
3. 打包新 Runtime 至独立稳定 JAR；配置当前 LAN 来源，重启三项服务并验证代理路径。

## 验证

执行助手测试、Runtime 定向 MVC/守卫测试、Spring 容器测试和打包。实际检查监听、健康、LAN 与回环读路径；经真实代理发送合法令牌但无业务参数的 POST，确认返回业务校验错误而非来源错误；执行未授权来源/令牌反例。不调用大模型、不新建用户模型。另一台设备访问受路由和防火墙影响，未实际测试则不宣称通过。

## 启动与回滚

前端在 `apps/web` 执行 `npm run dev -- --port 5177 --strictPort`，默认监听 `0.0.0.0`。仅回环模式可追加 `--host 127.0.0.1`。

Runtime 和助手启动时都设置 `OPM_TRUSTED_WEB_ORIGINS=http://本机IP:5177`；多个来源使用逗号分隔。助手可以在不提交的 `apps/assistant/.env.local` 中配置；Runtime 可用同名环境变量，或 `--opm.security.trusted-web-origins=http://本机IP:5177`。后端默认端口 17850、助手 17860，代理目标仍为 `127.0.0.1`，不需要暴露后端端口。通过 `http://本机IP:5177` 访问。

IP 或前端端口变化后，应同时更新两项后台的白名单并重启。该模式将本机开发工作台提供给可访问该前端端口的局域网设备，仍沿用本机会话而非多用户账号体系。

回滚：停止前端并用 `--host 127.0.0.1` 启动，清空两项后台的 `OPM_TRUSTED_WEB_ORIGINS` 后重启；必要时恢复旧稳定 Runtime JAR。保留当前存储目录，禁止重置数据库。

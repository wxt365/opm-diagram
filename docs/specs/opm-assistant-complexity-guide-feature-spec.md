# 智能助手复杂图建模指导

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change；Risk Level: L2；Task Type: feature。
Active Playbooks: none (primary)、testing。使用 skill-creator 更新项目内 Skill。

## 目标与非目标

将复杂业务图的上下文选择、细化策略、身份复用和稳定布局纳入生成指导，纠正“布局没有执行语义”的绝对表述，并给独立审查增加已核对的状态显示、展开和内缩放规则。后续补充系统价值与边界、前后条件、状态/属性维度、角色一致性、控制与分支逻辑、结构关系、OPL 一致性及需求中的数量/单位约束。

非目标：新增跨图写入、自动创建子图、状态显隐或阅读视图 UI、实现布局算法、完整 ISO 合规认证；不改写真实模型或历史对话。

## 范围与契约

允许修改两个 `apps/assistant/skills` 下的既有 Skill 和规则/策略文件、相关助手测试、`apps/assistant/README.md`、`docs/design/opm-conversational-modeling-design.md`、本规格及对应检查清单。禁止修改 Java、前端、运行时业务实现、依赖、数据库 schema、公共 API 字段、`.harness`、用户数据和 Git 远端。

沿用现有规则目录动态生成的审查 schema，增加规则 ID 后新报告必须逐项覆盖；来源条款由服务端赋值。当前 Skill 和生成指导升级为 1.2.0，旧未应用方案须重新审查后确认，历史报告保持可读。质量策略数值和 policy_version 保持 1.0.0，每张 OPD（总览及各层子图）主要对象与过程合计约 8～15 个是规划偏好，不替换计入状态/属性的 12 节点提示。简单图不为达到 8 个凑节点，超过 15 个先考虑阅读负担与细化，不删必要事实。

1.2.0 将九项审查扩为十五项，既有状态/变换规则扩充条款；没有新增 API 字段。当前快照不读取平台 OPL，OPL 一致性检查必须报告 NEEDS_INPUT 并说明尚未核对，不以自行改写的解释文本替代；不增加 OPL 读取工具。结构、逻辑、约束等表达只采用实际 capabilities，缺字段或能力不等于确定性标准错误。

## 验收

- CG-01：生成指导明确图的目的、按拥挤原因选择细化方式、共享身份、父子外部语义对应及缺少工具时的可执行边界；8～15 个主要对象与过程的合计目标适用于每张 OPD。拥挤影响理解时主动推荐具体子图方案，包含细化对象、子图问题、父图保留内容及边界；不删除必要事实、凑数或按节点数量编造子图。
- CG-02：布局规则区分普通阅读位置与内缩放的顺序/并行及对象空间或逻辑语义；优先局部调整，不由通用排版改变已确定业务含义。
- CG-03：审查新增状态显示、结构展开和内缩放顺序规则，引用已核对的 ISO 原文；无法证明上下文或缺少字段时不得确定性报错，不把普通分组或任意子图视为严格内缩放。
- CG-04：扩展规则报告可加载、完整绑定条款、缺项仍拒绝；NOT_APPLICABLE/NEEDS_INPUT 可正常绑定，明确 ERROR 仍阻断，质量建议保持非阻断且不修改投影。
- CG-05：同步设计文档和版本；执行 Skill 格式校验与助手定向/全量回归，不把契约测试当作真实大模型语义验证。
- CG-06：补充上述业务原则；系统级与局部任务区分，未知角色、边界、单位、数量不编造，不强制初始/终止状态或逐步确认。
- CG-07：新增系统目的/边界、前后条件、控制、逻辑、结构、OPL 六项审查，更新状态与角色一致性依据；证据不足用 NEEDS_INPUT，OPL 无平台文本时不声称通过。
- CG-08：十五项报告完整性、服务端条款绑定和业务遗漏依据通过契约测试；旧报告仍需重新审查。保留此前已复现的无关回归限制，不为通过全量测试修改运行时业务实现。

## 计划与边界确认

已检查干净 Git 状态、Skill 载入、动态规则 schema、版本应用守卫和现有测试；无需新增代码加载机制。先更新生成指导，再扩展审查目录与审查证据限制，最后补契约回归并同步设计。原文 SHA256 与现有来源一致；核对 PDF 第 87～93、102、122 页。

业务原则补充沿用此前未提交变更；允许与禁止范围不扩展。已核对 `scopedReviewSnapshot` 与 Runtime 读取范围，确认缺少 OPL 文本；核对新增摘要的原文第 18～20、27～29、39、53、55、76、78、87 页。先更新指导及规则，再做报告契约回归和文档同步。

## 验证与回滚

运行两份 Skill 的 quick_validate，助手 review/quality 定向测试和助手全量测试，以及 git diff --check；人工逐项检查 CG-01～03 的语义和工具边界。运行结果记录在检查清单。

回滚本次 Skill/目录/文档/测试变更，重启助手恢复原加载版本；不涉及数据迁移。服务启动时读取 Skill，因此已运行服务须重新加载后生效；若存在进行中的用户任务不打断，注明待重启。

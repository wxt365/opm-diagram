# 有效审查报告完成判定

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change; Risk Level: L2; Task Type: bugfix; Active Playbooks: none (primary).

目标：有效报告立即持久化，以校验通过的提交作为审查阶段完成信号，避免报告已提交但模型尾部异常被误判失败。允许修改助手tools/plan-finalizer、对应service测试及本规格清单；禁止API/schema/依赖/规则/权限/用户模型数据/.harness变化。

验收：REPORT-01 持久化成功后才设置内存报告和完成信号；REPORT-02 有效报告可结束审查，无有效报告的截断/异常/超时仍拒绝；REPORT-03 结束后拒绝迟到工具，停止/版本变化仍拒绝；REPORT-04 报告中的ERROR继续进入修正或阻断，全部图范围和最终确认检查不变。

计划：审查阶段等待模型结果或有效报告提交，成功提交关闭该阶段工具；保存报告后通知完成。针对截断、尾部异常、挂起、无报告、停止和有ERROR测试，然后重启。回滚：恢复代码重启，保留报告数据。

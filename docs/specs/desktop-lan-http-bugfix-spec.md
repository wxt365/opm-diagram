## 目标、复现和根因

用户在客户端保存局域网 HTTP 模型服务时，被“模型服务须使用 HTTPS；本机服务可使用 HTTP”拒绝。桌面校验只接受 HTTPS/loopback HTTP，未复用助手已有的显式私网 HTTP 来源机制；仅修改保存校验还会在启动助手时失败。原测试将全部远程 HTTP 视为非法，没有桌面私网配置的正向场景。

目标：允许 RFC1918 私网 IPv4 的 HTTP 地址，保存端口/路径；桌面仅将用户保存地址的精确 origin 传给受管助手 `OPM_MODEL_HTTP_ORIGIN`，不改变 Web 助手默认限制。HTTPS 和本机 HTTP 保持兼容。

非目标：不开放公网 HTTP、不更改 TLS 或重定向保护、不试用真实用户 Key、不调用用户网关生成模型。

## 边界、契约与验收

允许修改 `apps/desktop` 设置/受管助手参数/相关测试/设置提示与说明，必要时重建本机测试包；保留旧包和前序 Logo 工作。禁止修改业务 API/schema、Web 部署、用户设置/数据库和既有服务，不添加依赖。

- H1：HTTPS、本机及 10/8、172.16/12、192.168/16 HTTP 配置可保存并重读；公网 HTTP、非法协议、URL 认证/查询/片段拒绝。
- H2：受管助手收到精确 HTTP origin，并通过真实本地启动握手；不向网关发送测试请求。
- H3：设置页说明支持范围，定向回归通过；交付包反映修复，旧包保留。

## Plan / 边界确认

先补可失败测试，再对齐设置验证与助手精确 origin 参数，运行回归与设置界面检查，最后构建独立新版本测试包。用户已要求解决本机 HTTP 网关问题，授权上述必要修复和本机包更新。

## 验证与回滚

执行设置、受管助手与桌面测试；仅假 Key、本地进程和隔离目录，用户网关只验证地址接受，不宣称连通。回滚本轮增量及新包，保留旧 DMG、真实数据和其他未提交修改。

# 审查诊断与恢复

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change; Risk Level: L2; Task Type: bugfix; Active Playbooks: none (primary).

目标：read_model 返回当前及上轮平台诊断、审查状态/失败原因；报告一致性错误定位具体规则与字段；大方案审查有界延长，超时仍可复用既有重新审查入口。非目标：自动确认、放宽审查、重放上游请求、代码编辑授权。

允许修改 apps/assistant/src/{tools,review,stage-runner,plan-finalizer,service,review-retry}.mjs、新增同目录诊断模块、对应测试及本任务文档。允许内部诊断字段与工具返回扩展；禁止 HTTP/schema/依赖/安全/用户模型数据/.harness 和其他模块修改。

验收：DIAG-01 当前/上轮诊断区分，平台通过不冒称标准通过；DIAG-02 无效报告指出 rule_id、checks/ issues 字段路径和定向修正要求并保存，最多三次；DIAG-03 默认 120 秒，小方案不变，大方案每超出30步增加2秒，最多300秒；显式超时配置优先；DIAG-04 超时/无效报告仍阻断，重新审查复用步骤和命令身份，通过后一次确认。

计划：复用既有报告/重新审查入口，记录审查阶段信息；恢复新提案时保留上轮诊断快照；定向测试后重启。验证报告一致性、诊断读取、超时选择与既有审查恢复。回滚：恢复本次代码并重启；新增内部字段可忽略，不删除数据。

使用：超时后点击“重新审查”复用预览；咨询原因时 read_model 可读诊断。真实上游服务持续故障仍可能失败，不保证一次审查通过。

# OPM 工作台组件拆分

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

## 目标与范围
现有前端作为正式宿主，抽取可独立构建的 OPM 工作台；外部页面传入项目/模型上下文、模型展示快照或服务适配器后直接进入工作台。

非目标：重写 OPM 语义引擎、数据库迁移、改变后端协议、发布 npm 注册表。模型快照模式先提供只读展示和导航；完整编辑复用宿主提供的现有 Runtime 契约服务。

执行：change / L3 / feature / none (primary)。repo-profile、task-types、playbooks 在当前工作区缺失，按 AGENTS.md 与本规格执行。

允许：apps/web 的工作台、相关状态/API 适配层、库构建配置、组件测试、构建产物忽略规则；docs/specs、docs/integration；相关前端集成测试及配置。
禁止：services、数据库 schema、profiles、.harness；无关格式化、依赖升级和新增依赖。

## 契约
新增前端公共组件 OpmWorkbench、上下文/快照/服务类型及 JS 挂载接口。项目/模型管理、全局头部和路由属于宿主。组件头部可配置，嵌入默认隐藏。缺省显示默认项目、未命名模型、空白根 OPD，不创建后端资源、不请求原系统 API。默认实例状态独立；服务与宿主上下文可替换，旧请求不得污染新实例。
Runtime 适配器保持现有服务协议、草稿恢复、保存、版本、助手行为。后端 API 不变。

## 验收
- AC1：原路由页面通过新组件展示，现有编辑/保存/版本/导航/助手测试保持通过。
- AC2：不安装宿主路由/Pinia、不提供全局会话即可挂载默认工作台，且无网络调用。
- AC3：传入项目/模型和多 OPD 快照可展示、切换；替换数据清理旧选择；输入不被修改。
- AC4：同页实例状态、快捷键和卸载互不干扰；头部可开关，项目导航输出事件。
- AC5：独立 ESM 构建及类型声明可由外部消费，无宿主项目管理/路由依赖；提供接入文档和最小示例。

## 验证
先运行组件与原 WorkbenchView 定向 Vitest，再执行前端 typecheck/lint/全量 Vitest、应用及库构建。通过 Playwright 运行独立示例验证真实 X6 渲染和多实例。环境不支持原系统 E2E 时记录具体原因，不将静态检查当运行验证。

## 回滚
撤回本规格关联的前端组件/适配层及构建变更即可恢复原页面；不涉及后端数据迁移。原 API 与草稿持久化契约保持不变。

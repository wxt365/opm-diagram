# 脑图助手的保存回执与局部编辑

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode `change`，Risk Level `L3`，Task Type `feature`，Active Playbook `testing（primary）`。

- A1 两种脑图的回合状态依据 Runtime 回执显示已保存、未修改或保存失败。失败原因可见，模型的成功措辞不能覆盖失败状态。成功后沿用现有修订刷新。
- A2 分析助手可轻量读取节点结构，按需读取备注。局部工具接受预期修订和一批节点、顺序及关联操作，长备注留在服务端。业务自由树和 OPM 语义字段继续由各自契约验证。
- A3 局部编辑按稳定身份执行，校验树结构、关系、聚焦范围和版本。批次只保存一次，失败批次零写入，成功批次可按一次撤销。旧工具继续兼容既有整图整理。

允许修改助手的脑图工具、提示、回执、测试及本规格。复用现有前端状态与撤销接口。HTTP、数据库、正式模型契约及依赖沿用现有定义，这轮范围为局部保存与回执。

核对 A1–A3 后实施。先复现并修复错误回执，再接入合并和现有校验保存，最后跑服务回归和隔离工作台验收。回滚时撤回本规格对应的助手改动。

## 复查补充

Work Mode `change`，Risk Level `L2`，Task Type `bugfix`，Active Playbook `testing（primary）`。

- A4 OPM 脑图的写入在正式模型修订变化后会被拒绝。即使模型回复成功，工作台也须显示冲突原因。按同一回合的工具顺序执行版本检查和保存。

范围为助手工具入口、同一规格和回归测试。沿用现有工具参数、Runtime 接口及持久化方式。先复现零写入却显示成功，再修复并跑助手测试。回滚时撤回本节的工具入口和测试改动。

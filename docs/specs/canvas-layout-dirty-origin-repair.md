# 画布自动布局修正不触发未保存提示

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change；Risk Level: L2；Task Type: bugfix。
Active Playbooks: frontend-vue (primary)、testing（采用相邻 opm-platform 规则）。

## 目标与边界

加载时的状态容器修正只属于系统显示整理，不能把仅浏览的画布标成用户未保存。显式保存仍持久化整理后的布局，真实拖动、连线路径修改和用户应用自动布局继续受离开保护。允许修改画布布局 store、投影应用顺序、相关回归、工作台打包脚本和平台内置包引用。禁止修改后端、数据库 schema、公共 API、源 JSON、业务数据和无关界面，不引入依赖。

## 实施决策与清单

- DIRTY-01：分开保存待持久化的系统整理和用户布局；只有用户布局触发离开、刷新和切换保护。
- DIRTY-02：先整理服务端投影，再覆盖本地手动布局，使撤销和放弃回到正确显示基线。
- SAVE-01：手动保存合并系统整理和用户布局；保存失败可重试，重开不重复提交，自动修正不跨子图串用。
- PROTECT-01：手动拖动及改线仍提示，撤销全部手动改动后可直接离开；只读历史版本不写入。
- 范围已确认；先更新页面回归复现误报，再实现，最后运行相关测试、类型检查、打包及真实浏览器检查。

## 验证与回滚

验证仅浏览含旧状态的图并切换、真实拖动后离开、撤销、显式保存、失败重试、重开及只读版本。真实浏览器使用现有主题54读取验证；保存流程由可控回归模型验证，不保存用户测试期间的临时拖动。回滚此次布局逻辑及内置包引用，保留之前的属性分类修复。

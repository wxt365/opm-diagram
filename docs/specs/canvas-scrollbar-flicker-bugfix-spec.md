# 画布滚动条持续闪烁修复

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Active Playbooks：none (primary)、testing。

## 目标与证据

用户报告 macOS 客户端空画布横纵滚动条持续闪烁。隔离 0.1.2 最终应用、强制常驻 15px 滚动条可复现：窗口 1302×920 时 `.canvas-frame` 在 1057×378 和 1072×393 间反复变化，稳定采样 60 帧内出现 8 次切换；1441px 宽同样复现。证据 `/tmp/opm-scrollbar-probe.log`。

X6 `autoResize` 通过父容器整数 offsetWidth/offsetHeight 调整画布；父容器实际高度为小数（如 392.5px），整数尺寸撑出滚动条，滚动条改变父容器可用区域，再触发下一轮调整。目标是打断此尺寸反馈循环，同时保留窄屏/低高度时正常滚动。

原有静态布局验证未覆盖常驻滚动条与小数尺寸组合。本轮回归同时检查连续帧稳定性和画布实际尺寸不越界：仅检查稳定性在部分无头浏览器环境中不足以捕获旧实现的取整错误。

非目标：不改变画布模型、滚轮缩放/拖动语义、工具栏、数据库、API、助手网络实现；不自动打包或安装新客户端。

## 修改边界

允许修改 `apps/web/src/modules/workbench/OpdCanvas.vue` 的尺寸监听、相关定向测试、`tests/e2e` 最小浏览器回归及本规格/检查清单；构建 Web/组件产物供验证。禁止修改 `.harness`、业务持久化与契约、依赖、版本和旧包、真实用户数据。无 API/schema/依赖变更。

## 验收与验证

- S1：空图在小数尺寸、常驻滚动条和多种窗口宽度下，连续多帧尺寸稳定，不产生无内容溢出滚动条。
- S2：窄/低视口仍可滚动到画布内容；拖动、缩放及面板尺寸变化可用。
- S3：组件定向测试、浏览器回归和前端类型/构建通过；实际 Electron 隔离运行验证。

## Plan / 边界确认

先补会失败的浏览器回归，再关闭 X6 的取整数自动尺寸监听，使用已有 ResizeObserver 按真实内容区域向下取整更新尺寸，仅尺寸变化时调用 resize。保留最小画布尺寸和父层 overflow，不以隐藏全部滚动条遮盖问题。用户报告问题授权上述最小修复。

## 回滚

仅撤销本轮尺寸监听和测试增量，保留前序桌面与业务变更；不触碰用户工作区或现有安装包。

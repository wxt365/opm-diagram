# 仓储订单履约演示案例录入任务规格

## 执行元数据

- Work Mode：change
- Risk Level：L2
- Task Type：feature
- Active Playbooks：none (primary)
- 设计基线：`docs/design/opm-customer-demo.md`

## 目标

在当前本地 OPM Studio 中建立并保存设计基线定义的客户模型和工具校验模型，逐项记录实际可用能力、提交结果及重开结果。

## 非目标

- 不把仓储演示假设 H1 当作已确认的客户业务规则。
- 不修改工具实现、Profile、Golden、公共 API 或存储 schema。
- 不把只读候选、静态设计或已有 Golden 测试等同于本项目的运行验证。

## 范围与契约

- 允许：只向新建项目“仓储订单履约演示与工具校验”写入演示模型数据；新增本规格、对应 Checklist 和录入记录。
- 禁止：修改其他项目、现有源码及其脏文件、公共 API、数据库 schema、配置、依赖、测试和设计基线。
- 使用本地 Runtime 候选与草稿命令，按当前 token 逐条提交；不直接写数据库。API、schema 和配置契约不变。
- 能力不可用或存在阻断时，记录准确的未完成项，不伪造图形或绕过候选。

## 验收

- ENT-01：项目含客户、PROC、CTRL、STRUCT、NEG 五个独立模型，名称、身份及根 Context 可重开。
- ENT-02：客户 SD 和 SD1 的元素、状态及设计中的 M-01 至 M-15 尽量按候选逐条录入；缺项附原因。多级 OPD 按真实能力决定。
- ENT-03：四个工具模型按设计隔离数据；过程、控制、结构正例及拒绝路径逐项记录候选、提交或拒绝、投影与重开证据。
- ENT-04：保存并重开核对节点、Fact、OPL/trace 和校验；记录完成项、阻断项以及未执行项。

## 验证与回滚

- 先读取草稿投影，再对每条提交核对响应 token；完成后重新打开各模型核对内容。
- 运行工具提供的校验，比较关系身份和 OPL/trace；不把校验通过外推为业务认可或 ISO 认证。
- 回滚仅针对本演示项目中的本次录入数据，按 Runtime 删除命令及影响预览处理；不直接操作数据库。

## Plan

1. 核对当前项目草稿和工具候选，排除之前界面连续操作造成的漏项。
2. 逐条录入客户模型及四个独立校验模型，保持业务主图清晰。
3. 保存、重开并记录每项能力的实际状态；复核设计与运行差异。

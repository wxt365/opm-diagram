# 统一模型撤销与重做

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change; Risk Level: L3; Task Type: feature; Active Playbooks: none (primary).

## 目标与边界

工具栏、快捷键、画布菜单及操作历史共用撤销/重做调度。未保存的本地布局/个体颜色优先处理，保存后由持久化模型历史接管，不重复撤销；服务端支持连续撤销与重做，保存重开不丢失，发生新编辑时旧重做失效。

允许：apps/web/src 工作台入口、store/layout/history 模块及相关测试；services/local-runtime 草稿恢复/历史存储及相关测试；本规格和 checklist。必要时更新既有恢复相关规格说明最终行为。不新增依赖、数据库表、迁移或配置；不改助手逻辑、Runtime 公共接口路径、既有生成契约和无关模块。.harness repo-profile/task-types/playbooks 当前缺失，不新增 .harness 内容。

契约：沿用 RESTORE_OPERATION 的 UNDO/REDO 和历史项 recovery_action。HEAD 中最多一个 UNDO 和一个 REDO 候选，待重做原记录允许显示 UNDONE，内部恢复命令仍隐藏；其余已撤销记录继续隐藏。旧前端仍可通过历史按钮使用这些字段。两个内部持久恢复头和前驱节点仍存储于既有幂等命名空间。跨版本读取不开放恢复。智能整图/来源映射/schema 升级的原有恢复边界保持。

非目标：任意历史跳转、助手方案整图撤销、模型级默认调色盘配置撤销、文本框内部编辑撤销、跨模型/跨图本地撤销。服务器批量保存布局作为一次编辑；保存前多个本地移动可逐次撤销。

## 验收

- H1：服务端至少三步撤销/重做文档一致，保存及重新构造仓储可继续，交错方向正确；新编辑使 REDO 失效。
- H2：重复、过期、失败请求不破坏文档和恢复链；UNDO/REDO 仅原记录变更状态，历史候选与当前 token/摘要绑定。
- H3：工具栏和快捷键使用统一 canUndo/canRedo/undoLabel/redoLabel/undo/redo，历史按钮也调用统一执行入口；不需打开历史面板才启用。
- H4：优先本地历史，保存后清除本地历史并刷新服务端候选；本地撤销至基线前不越过本地修改，本地重做先于服务端重做；本地新编辑后不得重做旧服务端分支。
- H5：只读、保存/提交、待确认投递、候选创建、布局预览、助手生成/应用时禁用；输入框 Ctrl+Z 保留原生行为；失败显示提示并可重试。
- H6：定向前后端测试、助手回归、类型检查/契约检查按影响范围执行，报告实际结果和未执行项。

## Plan

先将持久化单向链扩展为两方向头与互为逆向的恢复点，原子更新原记录状态并发布候选。再为工作台增加统一调度和按 token 刷新的独立候选缓存；本地历史保存后清空并跟踪本地分支使服务端旧 REDO 暂不可用。最后接入按钮/键盘/菜单及助手忙碌守卫，并验证跨保存和方向切换。

## 验证与回滚

真实 SQLite 存储测试、HTTP Controller 测试（环境可用时 PostgreSQL）、工作台组件和 store 回归、web typecheck、定向 ESLint、既有生成契约校验。浏览器或外部服务未可用时明确记录，不以静态检查代替运行验证。

回滚：还原本任务文件差异；旧代码忽略 REDO 头，恢复命令仍为普通草稿编辑，不删除用户数据。

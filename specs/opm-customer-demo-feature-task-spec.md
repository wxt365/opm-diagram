# 客户演示与工具校验案例设计任务规格

## 执行元数据

- Work Mode：change
- Risk Level：L1
- Task Type：feature
- Active Playbooks：none (primary)
- 设计输入：`reference/ISO+19450-2024.pdf` C.6、`reference/自动化系统与集成 对象过程语言-20250914.pdf` 附录 A、`reference/基于OPL的架构建模方法20260425.pdf` 第 8 章。

## 目标

以“仓储订单履约与异常处理”建立客户可评审的案例设计，同时给出逐工具的输入、预期结果及失败判据。先完成设计，工作台绘制和运行验证留待后续实施阶段。

## 非目标

- 不把自拟仓储业务模型称为标准原文案例或标准符合性认证。
- 不实现尚未接通的架构方法检查、导入导出、仿真或自动执行业务流程。
- 不通过 demo 更改既有语义规则或生产项目数据。
- 本阶段不在系统内绘图，不运行浏览器用例，不把设计判定表述为实测结果。

## 边界与契约

- 允许：新增本规格、对应 Checklist 和 `docs/design/` 演示说明。
- 禁止：修改现有未提交文件、公共 API、数据库 schema、运行配置、依赖、Profile/Golden 基线及其他实现。
- 仅文档可以新增；API、schema、配置、依赖、测试及发布契约均不变。
- 本仓库 `.harness/repo-profile.md` 仍为 Harness 模板事实，实际命令以根 `package.json` 和 `tests/e2e/playwright.config.ts` 为准。

## 验收

- DMO-01：说明 reference 中已有案例及其与本演示的关系，区分标准例与自拟业务数据。
- DMO-02：客户主模型包含边界、OPD 层级、元素/状态字典和 15 条有明确所属图的 Fact；成功、不合格、超时三条路径闭合，并区分未经确认的业务规则。
- DMO-03：四个工具校验模型覆盖当前 16 类过程、8 类控制、10 类结构关系；具备完整基础数据字典、隔离规则、正例 Golden Oracle、拒绝错误码及非关系工具观察点。
- DMO-04：与实际工具目录、既有回归入口及 reference 来源核对一致；明确 Feature Value State 的工作台入口缺口及自动化预置边界；新增文件通过差异检查。

## 验证与回滚

- 设计阶段核对 34 类能力 ID、Golden case ID、引用路径、模型语义与差异空白；不执行运行验证，也不把静态检查当成工具通过。
- 回滚仅移除本任务新增的规格、Checklist 和演示说明。

## Plan

1. 从 reference 提取可沿用的 OPM 语义，核对当前工具目录与回归资产。
2. 将客户业务故事与工具语法验证拆为一个客户模型和 PROC/CTRL/STRUCT/NEG 四个校验模型，定义元素、状态、Fact、隔离规则与待确认假设。
3. 为全部关系工具映射 Golden Oracle，为非关系操作写可观察判据，最后检查编号、路径和文件差异。

待实施时确认：H1 业务完单条件、多级 OPD 候选、各关系在当前 Profile 下的启用状态。本阶段不以推测替代确认。

# DIGEST-V2-01 多层 OPD 保存失败修复

Work Mode：change；Risk Level：L3；Task Type：bugfix；Active Playbooks：none (primary), db-migration。

## 目标与边界

修复已启用混合保存的 V5 项目库拒绝 `SaveContentDigest/2` 内容，导致多层 OPD 保存返回 `PERSISTENCE_FAILED` 的问题。已有 `/1` 内容、草稿、历史、引用和不可变约束必须保留。当前工作台的待确认操作由原有恢复流程处理，不清理浏览器数据。

允许新增 V6 SQLite 迁移、Runtime 迁移注册与判定、定向迁移和保存测试，以及本规格和 Checklist。禁止修改旧 V1-V5 迁移、公共 API、SaveContent 摘要算法、前端待确认队列、依赖和用户模型内容；不做无关重构。

契约影响：`draft_content.digest_version` 从仅接收 `/1` 扩展为接收 `/1` 和 `/2`。已有 V5 混合保存库可自动升级到 V6；尚未受控启用 V3-V5 的已有库仍不得隐式升级。旧内容的摘要和历史引用保持原样。

## 验收

- D2-01：V5 库升级 V6 后，旧内容及引用数量与值保持一致，`integrity_check` 和 `foreign_key_check` 通过；重复打开不重复迁移。
- D2-02：`/2` 内容可保存、重开及读取固定历史；`/1` 仍可写入；未知版本、不合法 JSON、重复覆盖和内容更新仍被拒绝。
- D2-03：现有 V1/V2 库不因 Runtime 启动而自动启用混合保存；迁移失败保留恢复点，不留下部分升级。
- D2-04：在当前用户库副本上验证 V6、保存和重开，再处理运行实例并核对待确认操作可恢复。

验证：运行定向 Java 测试、构建、SQLite 完整性检查及当前库副本的真实保存流程；最后以工作台实际保存状态和重开结果确认。若浏览器待确认操作不能自动恢复，记录事实并保留原始数据。

回滚：停止新版本写入，使用迁移前恢复点回退数据库及旧运行版本；已有 `/2` 内容的库不得直接降级给只支持 V5 的运行版本。绝不删除原数据库或浏览器待确认记录。

Plan：先验证重建表的外键行为，再实现 V6 和受控启动判定，补迁移/保存回归；随后在数据库副本上演练，最后处理运行实例。

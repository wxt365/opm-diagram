# 项目流程边界回归修复

> 上游历史参考：本仓库仅迁入 OPM、SQLite 与桌面相关部分；业务建模、PostgreSQL 和内网部署不在范围内。原文状态及验证结果不自动适用于本仓库，实际迁移验证见 README 的迁移策略与本次迁移报告。

Work Mode: change; Risk Level: L2; Task Type: bugfix; Active Playbooks: none (primary).

## Spec

目标：修复同项目重新进入时旧打开错误残留，以及创建在途切换回收站后数量未更新。
非目标：启动配置、产品流程建议、其他既有功能改动。
允许：apps/web/src/stores/projectModel.ts、对应测试、apps/web/src/modules/projects/ProjectDetailView.vue 及测试、本规格和 checklist；按 AGENTS.md 第 7 条在既有 .harness/docs/agent-failures.md 追加漏验记录。禁止：其他 .harness 内容、公共 API、schema、后端、配置、依赖及无关文件。保留已有工作区差异。repo-profile/task-types/playbooks 缺失，按 AGENTS.md 执行。
契约影响：无；复用现有项目摘要查询及错误状态。

验收 R1：每次重新加载项目都清除旧打开错误、重置打开状态并使旧在途打开请求失效；随后新请求失败仍可显示并重试。
验收 R2：创建确认后不论当前模型列表范围，都独立刷新服务端活动模型数量；回收站不混入活动模型；摘要已包含新模型时不重复加一；过期摘要不覆盖新项目或新列表读取结果。
验收 R3：创建已成功但摘要刷新失败，不把创建当失败、不重新提交创建；独立提示可重试读取，保留当前列表范围。
验证：新增测试先复现 R1/R2，再验证修复、延迟响应与 R3 错误路径；完整前端测试、类型检查、定向 lint、diff 检查。
回滚：仅撤销本次增量，不覆盖此前修改；无数据迁移。

## Plan

1. 将打开请求版本失效与状态清理放到 loadProject 入口，保留项目身份的跨项目隔离。
2. 创建确认后，列表插入仍遵循范围，数量单独读取服务端摘要，避免用加一推算导致与在途列表摘要重复计算；按项目身份及列表读取序号保护回写。
3. 摘要失败使用已有 projectError 的非致命提示，重试沿用当前列表范围，不影响已确认创建结果。
4. 覆盖同项目重新进入、摘要两种响应次序、跨项目迟到响应及刷新失败重试，并执行回归。
